# Shell Repository Files

Root files of a repo whose product is shell scripts, hand-written or generated by bashly. How a
script is written is the `shell` skill's subject, and a bashly project's `src/` the `bashly`
skill's; this file covers only what surrounds them.

## Makefile

```makefile
.DEFAULT_GOAL := help
.PHONY: help test lint check

help: ## Show help
	@grep -E '^[a-zA-Z_-]+:.*?## .*$$' $(MAKEFILE_LIST) | sort | \
		awk 'BEGIN {FS = ":.*?## "}; {printf "  make %-13s - %s\n", $$1, $$2}'

test: ## Run the offline tests
	@bash test.sh

lint: ## shellcheck every script
	@command -v shellcheck >/dev/null || { echo "Error: shellcheck is required" >&2; exit 2; }
	@shellcheck <scripts>

check: test lint ## Full local check (run before commit)
```

- `lint` lists the scripts explicitly, or globs directories that hold nothing else. A script
  missing from the list is a script nobody checks.
- `test` needs no network and no container. Anything heavier is its own target (`smoke`, `e2e-*`)
  and stays out of `check`.
- A bashly project adds `generate` and `check-generated` — regenerate, then `git diff --exit-code`
  on the generated script — and CI runs `check-generated`. Its tests run through `bats`, as the
  `bashly` skill describes.

## .gitignore

The common block in `SKILL.md` is usually enough. Add `dist/` when the repo packages a release.

## CI

`references/github.md` → "Shell repo", or for a GitLab remote a job that installs the test
dependencies and runs `make check`.
